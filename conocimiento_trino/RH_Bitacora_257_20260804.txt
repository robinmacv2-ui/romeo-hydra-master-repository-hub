CAPÍTULO 1
Introducción a EMMOROR
La humanidad ha desarrollado herramientas para observar y comprender diferentes partes de la realidad:
las matemáticas describen patrones,
la física explica fenómenos naturales,
la biología estudia sistemas vivos,
la informática procesa información,
la inteligencia artificial encuentra relaciones complejas.
Sin embargo, estas disciplinas suelen estar separadas por herramientas distintas.
EMMOROR nace con la intención de crear un entorno donde diferentes tipos de conocimiento puedan representarse dentro de una misma estructura computacional.
El objetivo no es crear una "máquina que piense como un humano", sino construir un sistema capaz de:
representar modelos,
ejecutar experimentos,
analizar consecuencias,
encontrar relaciones,
comparar hipótesis,
documentar resultados.
---
CAPÍTULO 2
El problema que intenta resolver
Actualmente, para estudiar un fenómeno complejo normalmente se requiere utilizar muchas herramientas diferentes.
Ejemplo:
Un ecosistema requiere:
modelos matemáticos,
bases de datos,
simulaciones,
análisis estadístico,
programación especializada.
Un investigador debe conectar manualmente todos estos elementos.
EMMOROR propone una capa común:
Fenómeno real
      |
      ↓
Modelo matemático
      |
      ↓
Motor EMMOROR
      |
      ↓
Simulación + análisis + razonamiento
---
CAPÍTULO 3
Filosofía científica de EMMOROR
EMMOROR se basa en cinco principios:
1. Transparencia
Todo resultado debe poder rastrearse.
Un usuario debe saber:
qué datos entraron,
qué reglas se aplicaron,
cómo se obtuvo la conclusión.
---
2. Modularidad
Cada componente puede evolucionar independientemente.
Ejemplo:
El motor matemático puede mejorar sin modificar el sistema visual.
---
3. Reproducibilidad
Un experimento debe poder repetirse.
Si dos investigadores usan:
el mismo modelo,
los mismos parámetros,
las mismas condiciones,
deben obtener resultados comparables.
---
4. Accesibilidad
Una persona sin experiencia avanzada debe poder aprender a utilizarlo.
La complejidad debe estar dentro del sistema, no en el usuario.
---
5. Evolución progresiva
Cada versión debe ser útil.
No se busca construir todo desde el inicio.
La primera versión debe funcionar y crecer.
---

CAPÍTULO 7
Qué es un modelo matemático
Un modelo matemático es una representación simplificada de un sistema real utilizando elementos que pueden ser analizados mediante reglas.
La realidad siempre es más compleja que un modelo.
Por ejemplo:
Un árbol real tiene:
millones de células,
interacción con microorganismos,
respuesta al clima,
crecimiento irregular.
Pero un modelo inicial puede representar solamente:
altura,
edad,
cantidad de agua,
velocidad de crecimiento.
El modelo no es el árbol.
El modelo es una herramienta para estudiar ciertos aspectos del árbol.
---
7.1 Realidad → Modelo → Predicción
EMMOROR trabaja siguiendo este ciclo:
OBSERVACIÓN
     |
     ↓
REPRESENTACIÓN
     |
     ↓
MODELO MATEMÁTICO
     |
     ↓
SIMULACIÓN
     |
     ↓
COMPARACIÓN CON LA REALIDAD
Cada ciclo permite mejorar el modelo.
---
CAPÍTULO 8
Elementos fundamentales de un modelo
Todo modelo EMMOROR está formado por cinco componentes principales:
1. Entidades
Son los objetos del sistema.
Ejemplos:
planeta,
célula,
persona,
molécula,
población,
empresa.
En EMMOROR:
Entidad:
Planeta Tierra
Tiene propiedades:
masa = 5.97 × 10²⁴ kg
radio = 6371 km
temperatura media = 15 °C
---
2. Variables
Una variable es una característica que puede cambiar.
Ejemplo:
Temperatura:
T = 20 °C
Después:
T = 25 °C
La variable evolucionó.
Matemáticamente:
T(t)
significa:
"temperatura dependiendo del tiempo".
---
3. Parámetros
Un parámetro es un valor que normalmente permanece fijo durante un experimento.
Ejemplo:
Gravedad:
g=9.81m/s^2
En una simulación simple:
gravedad = constante
---
4. Estados
Un estado describe la condición actual del sistema.
Ejemplo:
Un automóvil:
Estado inicial:
velocidad = 0 km/h
combustible = 50 litros
motor = apagado
Después:
velocidad = 80 km/h
combustible = 40 litros
motor = encendido
El sistema cambió de estado.
---
5. Relaciones
Las relaciones describen cómo interactúan los elementos.
Ejemplo:
Más alimento
↓
Mayor población
↓
Mayor consumo
En matemáticas:
P=f(A)
Donde:
P = población
A = alimento disponible
---
CAPÍTULO 9
El concepto de sistema
EMMOROR no estudia objetos aislados.
Estudia sistemas.
Un sistema tiene:
Entrada
Información que recibe.
Ejemplo:
lluvia
Proceso
Reglas internas.
Ejemplo:
agua disponible aumenta crecimiento
Salida
Resultado.
Ejemplo:
mayor producción vegetal
Representación:
ENTRADA
   ↓
[SISTEMA]
   ↓
SALIDA
---
CAPÍTULO 10
Representación interna de EMMOROR
Para que una computadora pueda trabajar con un modelo, debe convertir conceptos humanos en estructuras digitales.
Ejemplo humano:
"Una población aumenta 5% cada año"
EMMOROR lo representa como:
Modelo:
Crecimiento poblacional
Entidad:
Población
Variable:
habitantes
Valor inicial:
1000
Regla:
habitantes(t+1)=habitantes(t)×1.05
---
CAPÍTULO 11
El lenguaje interno de modelos
EMMOROR utilizará una representación intermedia llamada:
EML
EMMOROR Modeling Language
Un lenguaje diseñado para describir sistemas.
Ejemplo:
SYSTEM Poblacion
VARIABLE habitantes
INITIAL 1000
RULE crecimiento:
habitantes = habitantes * 1.05
TIME 10
La idea es que una persona pueda leerlo casi como una descripción científica.

CAPÍTULO 13
La idea central: modelos que pueden evolucionar
Una característica importante de EMMOROR es que los modelos no deben ser objetos cerrados.
Un modelo puede crecer.
Ejemplo:
Primera versión:
Población = habitantes
Segunda versión:
Población
+
edad
+
natalidad
+
mortalidad
Tercera versión:
Población
+
economía
+
recursos
+
clima
El mismo modelo puede aumentar su complejidad progresivamente.

CAPÍTULO 14
Principio de coherencia del sistema
Para que EMMOROR funcione, todo modelo debe mantener coherencia.
Debe responder preguntas como:
¿Las unidades son compatibles?
¿Las reglas tienen sentido?
¿Los valores son posibles?
¿Existen contradicciones?
Ejemplo:
Incorrecto:
Temperatura = 300 metros
EMMOROR debe detectar:
Error:
unidad incompatible.
Temperatura requiere grados.

CAPÍTULO 16
Principio de construcción del sistema
EMMOROR será desarrollado como un sistema modular.
Esto significa que no será un único programa gigante, sino un conjunto de componentes especializados que trabajan juntos.
La razón es simple:
Un sistema científico debe poder crecer sin destruir lo que ya funciona.

ENTONCES

acción
     +
resultado

CAPÍTULO 28
Creando la primera entidad
Ahora construiremos el primer elemento del universo EMMOROR:
Una entidad.
Creamos:
core/entities.py
Concepto:
Una entidad tiene:
nombre,
tipo,
propiedades.
Ejemplo:
class Entity:
    def __init__(self, name, entity_type):
        self.name = name
        self.entity_type = entity_type
        self.properties = {}
¿Qué significa?
Creamos una plantilla.
Como un molde.
Después podemos crear infinitas entidades.
Ejemplo:
tierra = Entity(
    "Tierra",
    "Planeta"
)
Ahora EMMOROR entiende:
Existe un objeto llamado Tierra.

CAPÍTULO 31
Creando variables
Ahora necesitamos elementos que puedan cambiar.
Creamos:
core/variables.py
Una variable tendrá:
nombre,
valor,
unidad.
Ejemplo:
class Variable:
    def __init__(self,name,value,unit):
        self.name=name
        self.value=value
        self.unit=unit
Ejemplo:
temperature = Variable(
    "Temperatura",
    25,
    "Celsius"
)
EMMOROR ahora entiende:
Variable:
Temperatura
Valor:
25
Unidad:
Celsius
CAPÍTULO 32
Creando relaciones
Los sistemas no son colecciones aisladas.
Necesitamos conexiones.
Creamos:
core/relations.py
Una relación contiene:
origen,
acción,
destino.
Ejemplo:
class Relation:
    def __init__(self,origin,action,target):
        self.origin=origin
        self.action=action
        self.target=target
Ejemplo:
relation = Relation(
    "Temperatura",
    "aumenta",
    "Evaporación"
)
Resultado:
Temperatura aumenta Evaporación
